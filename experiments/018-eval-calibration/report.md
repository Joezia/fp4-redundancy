# 018 有损评估框架标定（gpt-oss-20b）

规格见 [docs/有损评估框架.md](../../docs/有损评估框架.md)。本实验在 gpt-oss-20b 的全部 MXFP4 专家权重上施加已知扰动，检查 `lossy_eval` 的四级指标是否正确、是否随误差单调，并测出测量下限。全部数字为本次实测；表格见 [results/tables.md](results/tables.md)，汇总见 [results/summary.json](results/summary.json)，图见 [results/calibration.png](results/calibration.png)。

## 结论

1. **框架正确。**
   - 恒等方法下，扰动流与原始流逐位相同：KL = 0，翻转数 = 0，各层误差为 0。
   - 微型随机模型上，与 transformers 前向逐位一致。
   - 真实 gpt-oss-20b 上，与 transformers 整模型前向的差别和两种 bf16 实现之间的差别同量级（见“与 transformers 对比”一节）。
   - 原模型的数值与公开结果一致：WikiText-2 困惑度 235.6，公开为 227–239；C4 为 718.2，公开为 709。这么高是因为 gpt-oss 是对话推理模型，不是基座模型，不是实现错误。
2. **指标随误差单调**，四级之间的关系清楚：
   - 权重误差会放大到层输出。白噪声的局部 MoE 误差比权重 NMSE 高约 4 dB；分组舍入在 3、4 bit 时与权重 NMSE 相当。
   - 误差逐层累积。
   - 路由对扰动很敏感：−40 dB 时已有约 6% 的 token 换了 top-4 专家。
3. **KL 是最灵敏、最可靠的指标；困惑度和任务精度都不适合单独使用。**
   - 困惑度在扰动下可能“变好”，例如 3 bit 舍入使 WikiText-2 从 235.6 降到 187.5，−20 dB 白噪声使 C4 从 718 降到 495。公开的 NVFP4 结果也出现同样现象：C4 从 709 降到 575。
   - 任务平均精度在 −20 dB 以内基本不变，但每个任务都有 2%–14% 的题目答案翻转，两个方向互相抵消。4 bit 舍入甚至让 MMLU 从 0.558 升到 0.616（McNemar z = +7.3）。
   - 因此，判断“没有损伤”必须看 KL 和翻转数，不能只看平均精度。
4. **可用区间：**
   - 权重 NMSE 约 −20 dB（4 bit 舍入，4.5 bpw）时，任务平均变化在 ±1 个百分点内，KL 约 0.25。
   - −12 dB（3 bit）时，任务平均降 3 个百分点，ARC 显著下降。
   - −10 dB 白噪声时降 20 个百分点。
   - −5 dB（2 bit）和 −2.4 dB 时，模型完全失效，KL 约 10，精度等于随机猜测。
   - −2.4 dB 是 10% 码率节省（约 0.4 bpw）在白信源上对应的率失真下界。所以如果误差像白噪声一样均匀分布，节省 10% 码率的代价是模型失效。有损方案能不能成立，取决于误差能否放到真实激活看不到的方向上；只看权重 NMSE 不够。

5. **测量下限：** 两种数学上等价的 bf16 计算之间，输出 KL 约 0.02，top-1 一致率约 0.92。transformers 的 bf16 与 fp32 之间也是如此。−40 dB 白噪声（KL 0.03）只比这个下限略高，所以小于约 0.03 的 KL 差别分辨不出。

## 设置

- **模型：** openai/gpt-oss-20b，revision 6cee5e8，24 层，每层 32 个专家，top-4。只替换专家权重 gate_up 和 down，共 19.1 G 个权重；注意力、路由、嵌入、输出头保持原样。
- **执行：** 逐层执行，原始流与扰动流同时前进；SDPA 注意力，sink 精确计入；在一块 A6000 上运行，峰值显存约 10 GiB。每种扰动约 32–45 分钟。
- **评估集：**
  - WikiText-2 test 和 C4 validation 各 64 个 2048 token 窗口，不加 BOS。
  - ARC-Easy 2000 题、ARC-Challenge 1172 题、HellaSwag 2000 题、PIQA 1838 题、WinoGrande 1267 题、MMLU 2000 题，0-shot，按 lm-evaluation-harness 的题面和打分规则；题量超过 2000 的任务用固定种子 20261126 抽样。
- **扰动：**
  - 白噪声：每个矩阵加高斯噪声，噪声功率等于目标 NMSE 乘以该矩阵的均方值，档位为 −40、−20、−10、−2.4 dB。为缩短时间，原计划的 −30、−15、−5、0 dB 没有跑。
  - 分组舍入：每行每 32 个元素一组，bf16 absmax scale，对称均匀舍入，分 4、3、2 bit，对应 4.5、3.5、2.5 bpw。
  - 恒等方法。
- **权重 NMSE 的口径：** 用每个矩阵 NMSE 的中位数。按能量合计的总 NMSE 几乎等于深层 down 矩阵的值：越深的层，down 矩阵的均方值越大，第 23 层约为 gate_up 的 10⁵ 倍；这是整体尺度变大，不是少数离群值。Ŵ 以 bf16 送入模型，bf16 舍入本身约 −56 dB，所以 −40 dB 档实测为 −39.9 dB。

## 观察到的规律

- **层输出放大：**
  - 白噪声的局部 MoE 误差比权重 NMSE 高约 4 dB（−40→−36，−20→−16.4），误差越大放大越多（−10→−5.3，−2.4→+4.9）。原因是真实激活落在权重增益较低的方向上，而白噪声在所有方向上一样大。
  - 分组舍入的误差与权重相关，3 bit 时局部误差与权重 NMSE 相当（−11.8→−12.1）。
  - 同为约 −20 dB 时，舍入与白噪声的局部误差几乎相同（−16.45 对 −16.40）。
- **逐层累积：**
  - −40 dB 白噪声在第 0 层的隐状态误差为 −49 dB，到末层累积为 −27 dB。
  - 个别层的局部误差远低于权重误差，例如第 6 层约 −64 dB，比 −40 dB 低 24 dB，各档扰动下都如此。可能是该层 MoE 输出主要来自不被扰动的部分（例如专家偏置），尚未核实。
  - 2 bit 舍入下，从第 1 层起 MoE 输出误差就达到 +60 dB，隐状态发散。
- **路由敏感：**
  - 换 top-4 专家集合的 token 比例：−40 dB 时为 6%，−20 dB 时为 27%，−10 dB 时为 67%，深层更高。
  - 换路由的 token 大多只换一个专家：−40 dB 时专家重合度为 0.98–0.99。
  - 这是 MoE 特有的放大机制：接近平局的路由决策会被微小误差翻转。
- **KL 随误差单调。** 同为约 −20 dB 时，白噪声与 4 bit 舍入的 KL 几乎相同（0.26 对 0.23），说明在这个区间里决定输出变化的主要是误差大小，而不是误差的形状。
- **任务精度的平台与断崖：** 权重 NMSE 在 −20 dB 以内时，平均精度基本不变；−12 dB 时开始下降；−10 dB 时大幅下降；−5 dB 时等于随机猜测。翻转数在平台区就已经很多，并且随误差单调增加：MMLU 在 −40 dB 时有 51 题翻转，−20 dB 时 277 题，3 bit 时 247 题。

## 与 transformers 对比和数值下限

脚本为 [hf_compare.py](hf_compare.py)，结果见 [results/hf_compare.json](results/hf_compare.json) 和 [results/hf_compare.log](results/hf_compare.log)。取 WikiText-2 和 C4 的前 4 个 2048 token 窗口（与主实验相同的切法），共 16376 个位置，用 5 种方式各算一遍完整的输出分布：

- **transformers fp32：** transformers 自带的 GptOssForCausalLM，`Mxfp4Config(dequantize=True)`，float32，关闭 TF32；放不下的层由 accelerate 卸载到 CPU。作为接近精确的参考。
- **transformers bf16：** 同一模型，bf16，eager 注意力，用 device_map 分到两块 GPU。
- **引擎 eager：** 本框架的引擎，transformers 的 eager 注意力。
- **引擎 SDPA：** 本框架的引擎，SDPA 注意力；8 个窗口一起跑，这是主实验的设置。
- **引擎 SDPA 单独：** 同上，但每个窗口单独跑。只改变矩阵乘法的形状，从而改变 bf16 的舍入。

| 对比（前者为参考） | KL 均值 | KL p99 | top-1 一致率 | 目标 token 平均 \|Δlog p\| |
|---|---|---|---|---|
| transformers fp32 vs transformers bf16 | 0.0233 | 0.45 | 0.917 | 0.159 |
| transformers fp32 vs 引擎 eager | 0.0234 | 0.43 | 0.916 | 0.153 |
| transformers fp32 vs 引擎 SDPA | 0.0227 | 0.44 | 0.920 | 0.148 |
| transformers fp32 vs 引擎 SDPA 单独 | 0.0221 | 0.41 | 0.920 | 0.155 |
| transformers bf16 vs 引擎 eager | 0.0180 | 0.31 | 0.932 | 0.131 |
| transformers bf16 vs 引擎 SDPA | 0.0205 | 0.35 | 0.924 | 0.138 |
| 引擎 eager vs 引擎 SDPA | 0.0206 | 0.39 | 0.928 | 0.131 |
| 引擎 SDPA 批量 vs 单独 | 0.0176 | 0.32 | 0.930 | 0.128 |

- **引擎和 transformers 一样准。** 以 fp32 为参考，引擎（KL 0.022–0.023）与 transformers 自己的 bf16（0.023）偏离程度相同。引擎与 transformers bf16 之间的差别（0.018–0.021），也和 transformers bf16 与它自己的 fp32 之间的差别相当。在这 4+4 个窗口上，困惑度分别为：fp32 402.0 / 1761.8，transformers bf16 398.9 / 1705.8，引擎 SDPA 397.7 / 1747.3。
- **数值下限比先前估计的高得多。** 任意两种数学上等价的 bf16 计算之间，输出 KL 均值约 0.018–0.023，top-1 一致率只有 0.92–0.93；仅改变批量组成也是如此。先前框架说明中“KL 最大约 0.003”的估计，来自两条短句，偏低了，现已更正。原因与 B 级观察一致：bf16 舍入改变了接近平局的 top-4 路由，路由差异再逐层放大。公开的 llama.cpp 测量也显示同样的敏感性：同一模型的 MXFP4 GGUF 对 F16，KLD 0.062，top-1 一致率 85.5%。
- **对标定结果的含义：**
  - 白噪声 −40 dB 的 KL 为 0.035 / 0.028，top-1 一致率为 0.897 / 0.906，只比数值下限高约 1.5 倍。它的任务翻转数（每个任务 18–51 题）也只能看作这个下限的量级。
  - −20 dB 及更大的扰动（KL ≥ 0.23）比下限高一个数量级以上，可以分辨。
  - 今后比较有损方法时：困惑度文本上 KL < 约 0.03 的差别视为分辨不出；方法之间的比较必须使用同一套运行设置。主实验中，原始流与扰动流的计算完全相同，所以恒等方法的 KL 精确为 0。但任何非零扰动，都会先触发这约 0.02 的混沌部分。

## 偏差与限制

- 白噪声只跑了 4 档（用户要求减少档位），−30、−15、−5、0 dB 没有跑。
- 多选题为 0-shot 对数似然打分，没有使用 gpt-oss 的 harmony 对话格式和推理模式，所以精度与官方成绩不可比；这里只比较扰动前后的变化。
- 生成类任务（GSM8K）没有做。
- 评估集规模有限：困惑度各 64 个窗口；多选题每个任务最多 2000 题，任务精度变化的统计误差约 ±1 个百分点，用 McNemar z 判断是否显著。
- DeepSeek-V4.1-Flash 尚未接入。
