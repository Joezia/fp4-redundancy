# 015：前 k 个码值已知时的平均码长（R3 的补充指标）

## 做法

- **样本：** 与 013 相同。
  - DeepSeek：与 008 完全相同的 516 个矩阵，即 B 计划前 172 个专家；运行前核对过清单。
  - Kimi-K3：与 009 完全相同的 552 个矩阵，即 `plan_552.json`。
- **代码：** [`kgram.py`](kgram.py)。只用 `redundancy.adapters.fp4` 读取码值 C 和块 scale E，计算是自己写的；没有使用 001 之前的结果、`runs/` 目录或 `fp4_redundancy` 的任何导入。
- **符号：** 原始的 16 个码值，+0 与 −0 不合并。
- **上下文：** 同一行内紧挨着的前 k 个码值，k = 0, 1, 2, 3, 4。行首不足 k 个时用较短的上下文：实现上把行首之前的位置填成 16（任何码值都不取这个值），所以“较短的上下文”自成一张表。
- **码长：**
  - 每个上下文一张计数表，每个符号初值 0.5（KT 估计）。逐个编码，编码后计数加 1；每个矩阵从零开始。
  - 同一上下文内，这个顺序编码的总码长与编码顺序无关，所以用闭式精确计算：每个上下文的码长为 −[Σ_s (lnΓ(n_s + ½) − lnΓ(½)) − (lnΓ(N + 8) − lnΓ(8))] / ln 2。
  - `selftest` 在小的合成数据上核对过：闭式结果与逐个编码的字面实现、以及 `redundancy.increment.dirichlet_bits` 一致（差 < 10⁻⁶ bit）。
  - 结果已包含学习成本，单位是 bit/码值（原始 4 bit）。块 scale 本身的码长不在其中。
- **三种数据：**
  - (a) 原始；
  - (b) 每行中每个 32 码值的块在块内随机打乱：保留块 scale 的影响，去掉块内顺序；
  - (c) 整行随机打乱。
  - 每个矩阵用固定种子 (20261124, 1)、(20261124, 2)，并断言打乱前后每行的码值多重集合相同。
- **加 scale：** 用（该码值所在块的 scale 字节，前 k 个码值）选表，k = 0..4，只算原始数据。
- **合并方式：** 按原始比特加权合并全部矩阵，即 Σ bit / Σ 码值数，因为每个码值的原始比特相同；另给逐矩阵的中位数。

## 结果

每格是“合并值（中位数）”，单位 bit/码值。k = 0 时三种数据本来就应该相等，实测也逐位相等，可以作为核对。

### 看到的情况

- **前 k 个码值带来的收益，几乎全部来自“同一块内的码值”，与块内顺序无关。**
  - (a) 与 (b) 的合并值在所有 k 上的差不超过 0.00002 bit/码值，逐矩阵的差在 −0.0046 到 +0.0008 之间。
  - 整行打乱 (c) 以后，收益完全消失，而且 k 越大越差，因为只剩学习成本。
  - 也就是说，前几个码值之所以有用，是因为它们与当前码值属于同一个 32 码值块、共用一个 scale，而不是因为相邻位置在数值上相关。
- **只看前 k 个码值时：**
  - DeepSeek：k = 3 最好，比 k = 0 少 0.0493 bit/码值。逐矩阵来看，478 个矩阵 k = 3 最好，38 个 k = 2 最好。
  - Kimi-K3：k = 2 最好，只少 0.0078；全部 552 个矩阵都是 k = 2 最好。
  - k = 4 时，两者的上下文数（17⁴ = 83,521）都太多，学习成本超过收益，比 k = 0 还差 0.038（DeepSeek）和 0.091（Kimi-K3）。
- **加上块 scale 以后，前 k 个码值几乎没有额外作用：**
  - 只用 scale（k = 0）就比不用 scale 少 0.1228（DeepSeek）、0.0548（Kimi-K3），已经超过前 k 个码值单独能带来的最大收益。
  - 在 scale 之上，DeepSeek 再加前 2 个码值只多省 0.0163（516 个矩阵全部是 k = 2 最好）。Kimi-K3 加任何 k 都更差：551 个矩阵 k = 0 最好，1 个 k = 1 最好。
  - 这与前一点一致：前几个码值提供的主要是“这个块偏大还是偏小”的信息，而 scale 已经直接给出了这一信息。
- **与 013 的对照（定性）：**
  - 013 中 R3 单独的节省为 DeepSeek 0.0471、Kimi-K3 0.0053 bit/权重。这两个值所用的上下文长度，分别正是 008、009 在 dev 上选定的 R3 参数：DeepSeek 取前 2 个码值，Kimi-K3 取前 1 个。
  - 本实验对应位置的数是 0.0466（k = 2）和 0.0052（k = 1）。
  - 两边的编码器不同：013 用合并 ±0 的分层自适应码，并有开关位；本实验是不合并 ±0 的单层 KT 码。所以这里只看量级是否一致，不比较具体数值。

## 运行时间

- 32 个进程，每个任务是一个专家的 3 个矩阵。
  - DeepSeek：276 秒（00:04:20–00:08:56），正式运行跑了 171 个专家；第 1 个专家先用单进程试跑，用时 12 秒，结果直接沿用。
  - Kimi-K3：323 秒（00:08:56–00:14:20）。
- CPU 时间合计 8,379 秒和 9,233 秒。单进程时每个矩阵约 4 秒；32 个进程同时跑时每个矩阵约 16 秒，原因没有单独测。
