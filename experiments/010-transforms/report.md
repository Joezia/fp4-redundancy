# 010：变换试验（T1–T3）与能力探针（P1）

编号说明：规格写的是 009，但 009 已用于 Kimi-K3，这里改为 010。

## 做法

- **样本**：DeepSeek FP4 专家矩阵，第 0、13、26、39 层，每层用固定种子（20261119）随机取 4 个专家，共 16 个专家、48 个矩阵：
  - 第 0 层：167、232、191、230
  - 第 13 层：27、193、127、267
  - 第 26 层：259、32、336、92
  - 第 39 层：9、126、70、88
- **码长计算**：全部用 `redundancy/increment.py` 的顺序自适应码长；边信息照实计费；参数沿用 008 在 dev 矩阵上选定的值。
- **对照**：008 链式模型（默认顺序）。w1 以同专家的 w3 为 R7 伙伴，w3、w2 没有伙伴。
- **净节省的口径**：008 链式码长减去试验码长（含边信息），除以受影响矩阵的权重数。
- **合成数据验证**：每个新方法先在合成数据上验证，全部通过；见 `results/synthetic_checks.json` 和 `results/p1_synthetic.json`。
  - T1：翻转的行与真值一致，SwiGLU 输出逐位相同，节省的比特数与行符号的 KT 码长一致（262 bit 对 259 bit）。
  - T2：带噪声的置换副本，匹配找回全部置换，节省远大于排列成本；独立数据上匹配后的相关与打乱基线相同（0.118 对 0.116），节省低于排列成本。
  - 列方向编码：上下行相关的数据上，列方向 R3 为行方向的 28 倍；独立同分布数据上各项约为 0。scale 流在“90% 抄上一行”的数据上，以上一行为上下文时为 0.98 bit/个，理论约 0.9。
  - T3：8 个原型生成的行被打乱后，两种最近邻排序都把同类行排在一起（97%，随机为 11%）。
  - P1：独立同分布数据上，探针码长 3.716，熵 3.714；马尔可夫数据上 2.664，条件熵 2.645。
- **新依赖**：规格要求用 `scipy.optimize.linear_sum_assignment`，因此安装了 scipy 1.17.1（`--no-deps`，numpy 不变）。

## 结果

| 项 | 受影响的矩阵 | 相对 008 的净节省（bit/权重） | 占 4.25 bit | 结论 |
| --- | --- | ---: | ---: | --- |
| T1 神经元符号规范化 | 每个专家的 w1、w2、w3 | +0.00005 | +0.001% | 输出逐位不变，但收益只是省掉每行一个相关符号，可以忽略 |
| T2 跨专家置换对齐 | 每对中专家 B 的 w1、w3 | −0.00095 | −0.022% | 对齐后找不到可用的跨专家信息，净值等于排列成本 |
| T2 基线（B 完全打乱） | 同上 | −0.00037 | −0.009% | 匹配本身用到了 B，带来低于排列成本的“选择收益” |
| T3 行重排 + 按列编码，按码值相关排序 | 每个专家的 w1、w3 | −0.0174 | −0.41% | 按列编码丢掉了块内相邻码值的信息（008 的 R3），远大于重排的收益 |

| T3 同上，原行序（不重排） | 同上 | −0.0155 | −0.36% | 按列编码本身就比按行差 |

| P1 神经网络探针（模型参数按 16 bit 计） | 同上 | −0.093 | −2.18% | 同上 |

## 各项说明

- **T1**：
  - 16 个专家翻转前后，SwiGLU 输出（float32，16 个随机输入）全部逐位相同；每个专家约一半神经元（50.4%）被翻转。
  - 给定 w1 编码 w3，码长减少 0.00015 bit/权重，正好是省掉的每行相关符号（每行约 1 bit）。第 26 层 R7 本来就没打开，所以那里没有收益。
  - w2 的码长变化为 −0.000003，即没有变化。
- **T2**：
  - 匹配后对应行的相关，24 对的中位数为 0.049（每对的 99% 分位，再取中位数为 0.072）；打乱基线为 0.046（0.062）。真实数据略高于基线，但很小。
  - 用对齐后的 A 作为 B 的上下文：w3 上 R7 一次也没被打开；w1 上，用 A 作伙伴都不如用自己的 w3。强制打开时为 −0.0013 到 −0.0021 bit/权重。
  - 净值等于 log2(2304!) 的排列成本，约 0.00095 bit/权重。
  - 打乱基线上 w1 反而有 +0.0012 bit/权重的“收益”：排列是看着 B 选的，排列里含有 B 的信息，所以这部分不超过排列成本（合成数据验证中也是如此）。为什么真实数据上同样的效应没有出现：不确定。
- **T3**：
  - 按列编码时，R3（上方的码值作上下文）在原行序和 scale 距离排序下为 0；按码值相关排序时为 0.0010 bit/权重。R4、R6 都在 0.00002 以下。R7 为 0.021，与按行编码相当（同一批 w1、w3 上 008 的 R7 为 0.019）。
  - 按列编码丢掉了 008 里 R3 的 0.0176 bit/权重（同一批 w1、w3）：那是同一块内前面码值的信息，按列编码时前面的码值来自别的块。
  - scale 流：008 的零阶码为 0.03085 bit/权重。以上一行为上下文：原行序 0.03080，按 scale 距离排序 0.02978，随机行序 0.03080。
  - 按 scale 距离重排确实让相邻行的 scale 相近，但省下的 0.00107 与排列成本 0.00095 相当。另外，以左边的 scale 为上下文、不重排时为 0.03064（省 0.0002），本次未计入表中。
- **P1**：
  - 网络：159,640 个参数，两层 256 宽的全连接网络。上下文为行内前 32 个码值、同列上方 8 行、w1 同位置码值（w3 用 w1[r, c]，w2 用 w1[c, r]，w1 本身没有）、所在块的 scale、行号、层号，另加矩阵角色。
  - 训练：每层前 2 个专家的 24 个矩阵，各取 40 万个位置。学习率（0.001 或 0.003）和轮数只在训练矩阵中留出的位置上选。
  - 测试：其余 24 个矩阵，每个随机取 50 万个位置，平均 3.709 bit/码值（标准误 0.0002）。链式模型在同一批矩阵上的码值部分为 3.626（不含 scale 流），网络在 w1、w2、w3 上都更差。
  - 不确定：可能是因为链式模型对每个矩阵自适应，而网络对所有矩阵用同一组参数；也可能是网络或训练量不足。本次没有区分这两种原因，所以 P1 只能说明“这个网络没有找到更多结构”，不能说明这种结构不存在。

## P1b：链式模型之上的修正探针（追加）

P1 的网络比链式模型差，回答不了“更强的模型能不能多省”。P1b 把链式模型放进探针里：输出 logits = log p_chain + f(特征)。f 的最后一层初始化为 0，所以初始时探针就是链式模型，训练只能在它之上修正。

### 做法与验证

- **逐位置的链式预测**（`p1b.py` 的 `chain_probs`）：
  - 按 008 链式模型实际打开的模式，重建与 `increment.fp4_codelen` 相同的各级上下文。
  - 父级预测在每块开头冻结，最细一级在块内逐个计数，得到每个码值位置的 15 元预测分布（R10 合并 ±0 后为 15 个符号）。
  - 48 个矩阵上，Σ −log2 p_chain 加 scale 流与边信息，与 `fp4_codelen` 及 008 存下的结果相差最大 3×10⁻¹⁵ bit/权重（要求 < 0.001）。
- **初始等同**：零初始化时，与链式模型相差 < 2×10⁻⁸ bit/权重（合成数据）；真实数据上第 0 轮的验证码长等于链式模型（3.61546 bit/码值）。
- **特征**：
  - P1 的全部特征：行内前 32 个码值、同列上方 8 个、块的 scale、行号、层号、矩阵角色。
  - 另一个矩阵同行 ±16 个位置的码值（含同位置）。
  - 本行全部块 scale 的均值与标准差。
  - 码值在块内的位置。
  - 另把 log p_chain 也作为 f 的输入（规格未列，消融显示它几乎不起作用）。
  - 所有码值都用 R10 合并后的值，这是链式模型实际传输的。
- **解码顺序与 P1 不同**：008 链式模型的 w1 以 w3 为上下文，所以 w3 先解码。为了让链式模型是探针的特例，探针按 w3 → w1 → w2 的顺序：w1 看 w3，w2 看 w1（w2[r, c] 对应 w1 的第 c 行、第 r 列附近），w3 不看别的矩阵。P1 是 w3 看 w1，这里做不到，否则就要去掉 008 中 w1 的 R7。
- **网络**：两层 256 宽的全连接网络，共 230,415 个参数。
- **训练**：用 P1 同样的 24 个训练矩阵，各取 40 万个位置。学习率 0.003 和轮数只用训练矩阵中留出的位置选定。
- **合成数据验证**（`results/p1b/synthetic.json`，全部通过）：
  - V-a：码值幅度只依赖块的 scale，是链式模型能看到的结构；增益为 0（4.6×10⁻⁹）。
  - V-b：在 V-a 上加入“非零码值的符号 = 本行前第 3 个与前第 20 个码值符号的异或”，概率 0.9 遵守规则，否则随机。增益 0.389 bit/权重，理论 0.373（104%）。
  - V-b 的距离改用 3 和 20，因为规格例子中的“相距 100”超出了探针只看前 32 个码值的范围。
  - 第一次运行时 V-a 为 0.030、V-b 理论值算错。原因：合成矩阵太小、结构复杂，链式模型的学习成本被离线模型省掉；理论值漏了“不遵守规则时符号随机”。改为只依赖 scale、200 万个位置，并改正理论值后重跑通过。

### 结果（24 个测试矩阵，2.83 亿个权重）

| 用法 | 码值码长（bit/码值） | 相对链式模型的净增益（bit/权重） | 占 4.25 bit |
| --- | ---: | ---: | ---: |
| 链式模型（008） | 3.6255 | — | — |
| 离线，模型成本摊到 24 个测试矩阵（每个参数 16 bit，0.0130 bit/权重） | 3.5752 | **0.0373** | 0.88% |
| 离线，模型成本摊到全模型 15,744 个专家（5.57×10¹¹ 个权重，0.0000066 bit/权重） | 3.5752 | **0.0503** | 1.18% |
| 在线（从离线模型出发，先预测、再更新；学习率 3×10⁻⁴ 只在 2 个训练矩阵上选） | 3.5743 | **0.0512** | 1.21% |

- **结论档位：> 0.02，存在明显遗漏的结构，需要专门分析。**
- 增益不是链式模型的学习成本（`p1b_diag.py`，`results/p1b/diag.json`）：
  - 按编码顺序分成十段，每段增益都在 0.050–0.052，没有集中在开头。
  - 链式模型的学习成本（码长减去它自己上下文的静态熵）只有 0.004；探针比这个静态熵下限还低 0.046。也就是说，探针用到了链式模型上下文之外的信息。
- 24 个测试矩阵每个都有增益（离线 0.031–0.063 bit/权重），w1、w2、w3 和四层都有。

### 消融（每次去掉一组特征重新训练，离线增益，未计模型成本）

| 去掉的特征组 | 去掉后的增益（bit/权重） | 减少 |
| --- | ---: | ---: |
| 无（完整探针） | 0.0503 | — |
| 行内前 32 个码值 | 0.0000 | 0.0503（全部） |
| 码值在块内的位置 | 0.0373 | 0.0130 |
| log p_chain 作为输入 | 0.0500 | 0.0004 |
| 行号、层号、矩阵角色 | 0.0501 | 0.0003 |
| 另一个矩阵同行 ±16 | 0.0501 | 0.0002 |
| 同列上方 8 个 | 0.0502 | 0.0001 |
| 块 scale 与本行 scale 均值、标准差 | 0.0503 | 0.0000 |

- 收益完全来自行内前面的码值，并且明显依赖“知道哪些前面的码值在同一个 32 块里”。
- 推测（未验证）：同一块中前面的码值透露了该块在 scale 之外的幅度分布。008 的 R3 只看前 2 个码值，已经拿到其中 0.018 bit/权重；008 的 V6 核查中，块内打乱后 R3 不变，说明它是块级信息。看到块内最多 31 个前面码值，还能再省约 0.05。
- 也可能与 MX 的 scale 规则有关：每块最大码值必须落在 4 或 6，007 的 R9 最大级别检查在 DeepSeek 上判为“存在”。
- 下一步的专门分析：为链式模型加一个“本块已出现码值”的上下文（例如已出现的最大级别、已出现大级别的个数与块内位置），看能拿回这 0.05 中的多少。

### 运行说明

- 时间：09:35–10:41，约 66 分钟。
- 离线模型训练完后，在线学习率的选择卡死：在已用 48 线程的 torch 进程里 fork 子进程，导致线程池死锁。改为 spawn 子进程后重跑这一步。离线模型直接复用；它的验证记录从同一次运行的日志（`results/p1b/run_train.log`）读回，写入 `fit_info.json`。
- 消融模型都只用学习率 0.003，与完整探针选定的相同。
