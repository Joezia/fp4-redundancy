# FP4 抽样初筛方案

模型：deepseek-ai/DeepSeek-V4.1-Flash，固定版本 `2cba9e42aa026125f3ed06c6d98c1db82f7ca027`。仅读取本地 checkpoint。

- 范围：尚未完成全模型的 50 个可执行方法 id，另跑 arithmetic 同输入基线；复用别名仍单列，未实现技术不执行。
- 样本：文本层0/13/26/39与 MTP 层0/2，每层取实际编号最小/最大的两个路由专家，各取 w1/w2/w3，共36块；不假设 MTP 与文本层专家数相同。
- 位置：按层/专家/参数角色循环分配头/中/尾，各12块，事先固定，不根据压缩结果挑选。
- 分块：权重＋scale 合计上限64 KiB，完整连续行、原始顺序，scale 配对且独立编码。
- 数据量：权重 2110464 bytes，scale 131904 bytes，合计 2242368 bytes。
- 并行：8个方法同时运行，每方法4进程，内部线程1。既有 A2 全模型任务继续运行。
- 参数：本轮使用现有固定配置，先观察所有技术；矩阵尺寸/秩的搜索另轮进行。
- 验证/计费：沿用现有 runner，新实例逐字节解码，计入全部 payload、元数据、字典/参数/纠错等；同时报告原始收益与匹配算术基线净收益。
- 保存：`runs/<method>/fp4_sample/` 下保存状态、输入/产物哈希、逐块结果及汇总；验证后丢弃码流。
- 解读：这是一组分层探索样本，不是全模型无偏估计。64 KiB 的表/参数占比可能不同于1 MiB全模型设置；不直接与旧结果混算。

完整方法清单、精确块索引见 `plan.json`，原始范围/形状见 `samples.json`。未实现项：tans。
使用 `source .env` 后执行 `python3 scripts/run_fp4_sample.py run`；中断后同命令自动续跑。
## VQ 参数探索

沿用原 FP4 抽样的同36个块、64 KiB上限、原序与独立scale，总原始大小2,242,368 bytes。

- 原数值VQ和零阶算术编码各重跑一次作对照，另存新目录；不覆盖原结果。
- 一个新完整插件 vq_codeword：实际完整码字向量 medoid，packed 码本、索引、精确 XOR 纠错；C++ 实现，复用原 A1 算术编码。
- 原序分层确定性抖动抽取至多2048个训练向量，五轮分配/medoid更新，解码不训练。
- 主网格：向量长度2/4/8 × 码本上限4/16/64，共9组，使用预计码长目标和纠错模型auto。
- 消融：8维/16中心的 Hamming＋共享纠错、码长目标＋共享纠错、码长目标＋条件纠错，共3组。
- 条件纠错按中心×位置统计；每表先比较估计收益与表成本，低收益时用共享模型。auto再按完整产物实际可变成本比较共享/条件方案。
- 无原样或算术-only回退；共享回退仍保留VQ码本、索引和纠错完整流程。
- 所有方法逐字节验证，记录完整大小、索引/纠错/码本/元数据成本及原始/净收益；按方法存 runs/<方法>/vq_optimization/<配置>/。
- 最多4组×4进程并行，内部线程1；不运行全模型。
- 保存全部配置结果。“最佳”只表示这36块上的探索最优，不声称独立验证或全模型最优。

此处为相同36片段上的历史参数探索；参数、执行和验证记录并入各JSON的`vq_parameter_exploration`字段，CSV以`variant`列区分配置。
