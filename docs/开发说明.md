# 开发说明

## 输入

`examples/model-manifest.json` 是输入样例。一个 target 是独立编码单元，
包含权重和 scales 等原生组件；组件声明文件、offset、length、role、storage_format。
清单保留 model/revision、logical_shape、structure 和 inference。
同一文件的范围不重叠；具体格式适配器确认 packing、scale 对应和索引覆盖范围。
固定数据边界写在 README，不再要求每份清单重复声明 policy。

## 连续 FP4 word 配置

完整插件通过参数 `unit_bits` 增加配置，默认4保持原码流与结果；8/16/32分别合并2/4/8个连续完整码字。
64仅用于Delta/XOR/FPC/RLE及其匹配算术对照。逐方法范围、等价配置和待复核边界见[支持清单](../experiments/grouped-units/audit.md)。

- 固定原目标和外层1 MiB块、原packed基线及独立scale。仅FP4分组；scale继续原表示独立编码。
- 原nibble顺序归一后，首码字在word低4位，word小端；按原物理行分组，行尾补零并保存原字节数/有效码字数/原生padding。解码检查补零并恢复所有原字节，不跨行合并word。
- A1/A2等8/16配置复用现有完整符号实现，真实扩大字母表及上下文。32-bit熵编码用已出现word的稀疏映射并计费；rANS超过65,536个已出现符号记`resource_limited`。PPM/CTW三阶历史对应`3*unit_bits/4`个原权重；PAQ/CABAC/神经模型的word特征与更新边界随宽度改变，仍是现有适配而非完整PAQ/CABAC。
- 数值法8/16/32输入是精确转float64的无符号整数word，经原有二次幂归一；保留原训练、块形状、秩和Q20参数。Q20整数实际解码后，四舍五入（正半值向上）并裁到`[0,2^b−1]`，以完整word XOR纠错，再按低nibble在先序列化给原A1算术编码。4-bit保留原方法语义，不能将宽word整数距离解释为真实FP4权重距离。
- FPC32/64前缀格式v2仍每word4bit（预测选择＋残差字节类），字节类7表示8字节，实际7字节残差补至8字节。RLE8起格式v2按真实word宽度存符号＋LEB128 run。SZ32保留Lorenzo、精确反馈及原Huffman＋Zstd；LZ77/LZSS保持原字节窗口跨度，最短匹配仍3word。CDC8新增真正packed字节Gear及32/128/512字节边界尺度。VQ16/32保留medoid/码长目标，稀疏成本表替代全字母表，纠错为nibble单位，auto比较共享/条件模型的完整成本。
- 内部向量/变换块维度及秩保留，以word计，因此覆盖原权重数乘`unit_bits/4`；二维预测行宽相应缩短并记录。没有新增全局字段拆分、重排或阶段组合接口。

`python3 scripts/build_grouped_units.py` 构建独立私有宽word库，不覆盖旧库。
`python3 scripts/build_grouped_jpeg.py` 构建JPEG-LS宽word配置的独立缓冲区修正库：CharLS预估容量不是上限，遇到容量不足时重新初始化编码器并倍增，最高64 MiB；算法、NEAR=0、行布局及B封装不变。原失败记录保留，修正后8/16-bit结果存于`unit8-buffer-v2`/`unit16-buffer-v2`。
编译时生成现有C3/D数值实现的类型/输入桥接副本，核心训练及分解源码仍复用原文件；依赖哈希随运行保存。
FPC扩展修改日期为2026-11-10，保留原研究/教学许可，完整声明见[原FPC许可证](../native/predictive/FPC-NOTICE.txt)。
`PYTHONPATH=src python3 -m unittest discover -s tests` 检查全部插件；`python3 scripts/check_grouped_units.py` 检查新增宽整数路径的ASan/UBSan。
现有六张完整矩阵的202配置计划、逐配置/矩阵/块成本及原始状态分别位于`experiments/grouped-units/`与`runs/<技术>/grouped_units/unit<bits>/`。
同宽度零阶算术对照沿用现有runner，两种收益完整计费；等价项只关联、不重复计算。没有“最佳配置”组合，所有成功和膨胀结果保留。

## 增加一种技术

技术和无损方案由用户确定，A/B/C/D 均可接入，不需要填写或审批“无损适配状态”。
实现时只需：

1. 在 `catalog.py` 列出 id、名称、类别。
2. 新建方法模块，填写 `types.py` 的 `MethodSpec`：来源/版本及适配差异简述；
   实现 `check_support(target, parameters)`、`encode(target, components, parameters)`
   和 `decode(artifact)`。每个模块封装一种完整技术，不要求有预测或残差阶段。
3. 用微小合成数据检查完整字节往返，然后把方法工厂加入使用方的 `Registry`。
   内置实现统一在 `catalog.builtin_registry()` 注册。

`check_support` 只回答当前实现能否处理该目标的格式和参数，不评判技术研究价值。
`encode` 接收组件 id → 原始 bytes；`decode` 只接收 `EncodedArtifact`，
在新实例上恢复同一组件集合及其全部 bytes。必要参数、表、参考和布局均包含在
`payload` 或 `side_information` 中，两者全部计费，不能依赖源文件或编码器缓存。
方法需要预测或预处理时，插件内部包含配套无损存储。

标识和说明按实际实现填写。若改变原方法，使用明确的适配名称及独立 id，
简述保留了什么、改了什么即可；不用提交多阶段评审表。

## A2 概率建模的接入与比较

PPM、CTW、Context Mixing/PAQ、CABAC 概率建模适配、Neural Entropy Models 等，
固定以 A1 的 C/C++ 算术编码器为后端，优先复用已有实现，不遍历 Huffman、rANS、Rice 等后端。
每项仍是“该技术概率模型＋算术编码”的完整插件；只在插件内部复用代码，不新增自由组合的阶段框架。
仅借用概率模型时使用适配名称；CABAC/CAVLC 等自带编码机制的完整方案保留原机制、单独标识和比较，
不强行替换后端，也不把这类完整方案的收益全部归因于概率模型。

从 A2 起只保留原始完整符号和原序，PPM 指数分离版已移除；A1 已有的指数分离对照保留。
A2 对照固定为“零阶概率模型＋同一算术编码器” `arithmetic`。比较使用同一 checkpoint 版本、
相同组件字节、符号映射、原序、实际分块边界以及编码器版本、整数 CDF 精度和结束规则。
若技术适配改变输入映射或编码器配置，应补充匹配的零阶对照，不能直接沿用不同配置的旧结果。
FP4 始终保持完整码字，scale 独立建模；上下文及自适应状态在各独立块/组件流重新初始化。

编解码两端依据已解码数据和产物内的必要附加信息重建一致的概率/CDF 与更新状态；
神经模型若使用浮点推理，也须保证最终整数 CDF 一致。
全部必要参数、初始状态、表、映射及神经模型权重等均完整计费，不依赖未计费的外部数据。
仅在相同块和组件均逐字节验证成功时配对比较：
`净节省字节 = 零阶完整产物大小 - A2 完整产物大小`，比例以零阶完整产物大小为分母，允许负值。
同时记录 `原始节省字节 = 原始组件字节 - A2 完整产物大小`，比例以原始组件字节为分母，允许负值。
保留块大小、payload、元数据和总大小；不以预测熵代替实际编码结果。

A2 已接入 `ppm`、`ctw`、`paq`、`cabac`、`neural_entropy` 五个概率模型适配及 `cavlc` 完整编码适配。
在 `MethodSpec.baseline_method_id` 中声明 `arithmetic` 后，runner 自动在相同源字节上计算基线，
同一块内可复用已算出的匹配基线；不会遍历其他 A1 后端。结果中的 `saving_bytes/saving_fraction`
保留原始收益，`baseline_comparison` 保存基线状态、完整大小、`net_saving_bytes/net_saving_fraction`。
汇总的原始比例名为 `saving_fraction_on_verified_bytes`；CSV 同时导出两种收益及配对原始字节数。
净收益只汇总双方均验证成功的同一批块，并保留配对覆盖范围；基线失败或缺失时净收益留空，
A2 自身成功的原始收益仍保留。基线状态与必要码表随结果保存，不计入 A2 自身产物大小。
`baseline_comparison.kind` 区分 `probability_model` 与 `complete_scheme`；CAVLC 属于后者，
其净收益包含编码机制差异，不能当作纯上下文收益。CSV 同样保留此标记。

### 已接入的 PPM 适配

复用 [Nayuki 的 C++ PPM 参考模型](https://github.com/nayuki/Reference-arithmetic-coding/tree/ab6ee50afec04d235a4b82d17f407f0fd2b42e9a/cpp)，
保留三阶上下文、escape 频率 1、逐级回退、无 exclusion、order −1 均匀分布和符号后更新。
已核对 7-Zip PPMd 的字节模型；本次选可扩展字母表的 Nayuki 参考实现，保持完整 BF16/FP4 码字。
为控制开销，改用稀疏上下文与 Fenwick 根频率表，上限 65,536 个上下文；
下次更新会超限时确定性重置模型和历史。各频率表总计数到 `2^20` 时按 `(f+1)//2` 重缩放。
按已保存的符号数量结束，替代上游 EOF；不是 PPMd，也不声称兼容原参考程序码流。
模型参数、版本、字母表、结束位数均包含在计费产物中；动态上下文由已解码码字重建，块和组件间不共享。
YAECL 只新增稀疏 CDF 的区间接口，仍用相同 32-bit 区间、24-bit 整数 CDF 和结束规则；
已有 A1 码流回归向量保持一致。来源、固定 commit、许可证和修改说明见 `native/third_party/sources.json`。
已完成合成数据验证；A2 六项全模型并行运行已启动，实际状态与进度统一见 README。

### 其余 A2 适配

| id | 保留机制及明确差异 | 后端 |
| --- | --- | --- |

CTW 迁移核心递推并改为定点计算，不依赖 Rcpp，也不宣称与原版浮点 BCT 的概率逐位相同。
PAQ、CABAC 和神经模型在方法内部用二元条件概率构造整码字 CDF；不拆字段、不生成 bit-plane 或额外流，
最终对每个完整码字只调用一次相同算术区间更新，原序不变。
神经模型的四个历史完整码字、当前已知前缀和位置构成特征；训练只发生在当前组件，所有量化权重计费。
编码与解码都使用同一整数推理，模型权重量化只影响概率和码长，不改变原始权重字节。
上述所有模型及状态在块和组件边界重置；版本、固定参数和需要的数据都包含在产物中。
全部源码、固定版本、许可证、来源核对和本地差异见 `native/third_party/sources.json`。


## B 类预测技术

十二个完整插件以 C/C++ 执行，Python 复用现有产物包装、分块和结果记录；不新增可自由组合的阶段接口。
FP4/FP8/BF16 分别处理完整 4/8/16-bit 原始码字，F32 继续按原始字节。scale 是独立组件，全部状态独立初始化。
这批是码字域适配，不将 FP4/BF16 解量化为浮点数；特殊位模式、packed 顺序与 padding 逐字节恢复。
每组件上限 4 MiB，默认分块仍为权重和 scale 合计 1 MiB；未增加模型实验。

| 方法 id | 保留机制与适配范围 | 固定后端 |
| --- | --- | --- |
| `delta` / `xor` | 前一码字差分 / XOR，零初始参考 | 现有 A1 算术编码 |
| `dpcm_lossless` | 二阶固定预测 `2*x[-1]-x[-2]`，零边界，无量化 | 同上 |
| `adpcm_like_fp4` | libsndfile 1.2.2 IMA：原步长/index 自适应、4-bit 决策及饱和重建反馈；另加精确模补偿，决策和补偿各自编码；不是 G.726 | 同上 |
| `jpeg_ls_like_fp4` | CharLS 2.4.2，明确 `NEAR=0`，保留完整上下文修正、run mode、自适应 Golomb 类编码；完整码字映射为灰度样本，超尺寸时连续条带独立编码 | 原 JPEG-LS 编码 |
| `png_filtering` | None/Sub/Up/Average/Paeth 五类滤波及原 tie 规则，按行选最小模残差幅度；从 byte 扩展到完整码字，保存行滤波号；不是完整 PNG | A1 算术编码，无 DEFLATE |
| `fpc_like_fp4` | FPC 1.1 的 FCM/DFCM、较小 XOR 选择、selector 与零字节专用前缀；4/8/16-bit、宽度适配 hash、每表 4096 槽 | FPC 专用前缀＋残差字节 |
| `sz_like_lossless` | 所选 SZ3 一阶 1D/2D Lorenzo；原误差有界量化改为精确整数模残差，编码端反馈原码字，解码端反馈恢复码字；不包括回归/插值/自动选择 | 原 SZ3 Huffman＋Zstd 1.5.7 level 3 |
| `lpc_lossless` | FLAC 自相关/Levinson-Durbin 递推；前至多 8192 码字拟合八阶，保存全部 Q12 系数；不是 FLAC 码流 | A1 算术编码 |

| `motion_compensation` | 本组件连续 16 行作参考条带，16×4 块、整数位移搜索 dx∈{-8,-4,0,4,8}/dy∈{-4,0,4}，保存位移；只引用已恢复前条带 | 同上 |
| `intra_directional` | 8×8 块，垂直/水平/两条对角线的四方向整数边界预测，保存方向；不是完整 H.264 九模式 | 同上 |

差分等数值补偿使用模 `2^w` 表示，`w` 是完整码字宽度；中间预测用有符号 64-bit 整数，
解码按同一规则相加取模，可恢复全部原始位模式。LPC/LTP 系数量化只影响预测，精确补偿不量化；
拟合可使用浮点数，但解码只使用产物内的整数参数。IMA 则保持原量化重建反馈不变，
外加补偿只用于恢复输出，不进入 IMA 反馈；初始 sample/index 都为零，两个码流及全部表均计费。
SZ3 的替换没有采用“误差设零”或原样保存证明法；模残差覆盖全部输入，不依赖浮点量化器或特殊值回退。

空间方法只在已知且对齐的原生 `storage_shapes` 上使用物理行；未知或切到半行的组件明确使用一维流，
不猜测二维布局。没有转置、重排或跨组件参考。离线参考条带不表示推理中的时间帧或硬件访问单位。
F32 的行宽按原生列数乘 4 个字节计算。JPEG-LS 内部条带、方向/滤波号、位移、系数、边界及布局都在计费产物内。
SZ3 为单独计量元数据，将原 Huffman 表留在 side information，最终 Zstd 只压 Huffman 数据流；
保留两个上游编码引擎，封装位置与原 SZ3 不同。JPEG-LS/FPC 的内部控制码属于 payload，和现有编码统计一致。

B 同时记录原始收益及相对同组件、同分块 `arithmetic` 基线的净收益，统一标为 `complete_scheme`。
算术后端沿用 A1 的整数 CDF/结束规则；专用后端的净收益包含编码机制差异，不能全部归因于预测。
现有 runner/SQLite/CSV 原样记录 payload、元数据、合计、两种收益及双方验证覆盖；不遍历其他 A1 后端。
源码版本、来源、许可证、原始参考和修改说明见 `native/predictive/third_party/sources.json`。
FPC 上游采用 Cornell 非商业研究/教学许可，完整声明随源码保留；不将其标作 BSD/MIT。

当前适配已检查两端状态、溢出/模边界、全部 BF16 位模式、FP4 两种 nibble 顺序、独立 scale 与新进程解码。
尚需复核的扩展范围是：原版 FP64 FPC 兼容性、SZ3 其他预测器、G.726 自适应状态、完整视频/Opus 机制，
均不属于这批已实现变体；接入这些变体前需各自核对状态与补偿，不能由当前测试外推。
真实模型上的收益和运行速度尚未验证，尤其 4-bit FPC 的 selector/字节残差可能明显膨胀，必须保留实测负收益。

B 使用独立 `build/libfp4_predictive.so`，不覆盖正在运行的 A2 库。六项已有 A2 运行的原代码和构建
已冻结在 `runs/.a2-runtime/`，供中断后续跑：
`PYTHONPATH=runs/.a2-runtime/src python3 -m fp4_redundancy run "$SNAPSHOT" --output "$FP4_RUNS_DIR/方法id" --methods 方法id --workers 16 --chunk-bytes 1048576 --resume`。
使用绝对的 snapshot/output 路径，恢复既有目录；其配置与指纹保持原运行版本。

## C 类重复与共享模式

16 个新 C/C++ 完整插件及一个关联别名。每组件、每分析块独立；尺度、字典、参考、语法、训练和自适应状态均不跨块共享。
符号为完整 FP4/FP8/BF16 码字，F32 延续原始字节表示。统一报告原始收益及相对相同输入/分块 `arithmetic` 的净收益，

**参考与编码。** C2 在本组件前缀候选中按含参考大小选择；非单符号组件保留非空付费参考。
参考完整 packed 存入计费元数据，解码先恢复该前缀，随后解码剩余数据；RLZ 的 suffix array 可由参考重建，无需重复保存。
Xdelta 只接原生 C 内存 API，保留 VCDIFF 编码；FP4 为每个完整码字一个字节的内部输入，BF16 为 little-endian bytes，
最终基线和恢复仍按原 packed bytes。C1/C2 自身 token/字典/语法规则直接编码，不拿通用压缩器代替算法。
语法、动态字典、重叠引用和所有源范围都有解码边界检查；哈希是筛选器，完整相等检查决定是否引用。
算法内的去重块/CDC 块与外层默认 1 MiB 分析块不同，各层边界和必需长度均在产物中或可确定性恢复。

**C3 训练与恢复。** 连续八个完整码字组成向量，不改变输出的逻辑顺序。训练使用原生浮点组件的实际数值，
FP4 是 E2M1FN，FP8/BF16 按原生格式，E8M0 scale 按其实际幂值；权重训练不混入伴随 scale。
F32 按用户选择处理原始 byte 值。固定 checkpoint 的 `inference/kernel.py` 明确定义 E2M1FN，适配器已记录
`fp4_value_format=E2M1FN`；同版本 `inference/convert.py:53` 和 `model.py:26/30` 确认 E4M3FN / E8M0FNU。
通用清单缺少 FP4 数值格式证据时，C3 返回不适用，仍可运行 C1/C2。
每组件用保存的二次幂指数归一化并 Q20 取整，取前至多 512 向量、K≤16、Lloyd 八轮；尾向量补零并按原数量截回。
NaN/Inf 仅在训练表示中映射为零；负零及所有特殊原码字均由精确纠错保存。

OPQ 交替四轮并最终重新拟合，完整保存 Q20 旋转矩阵；它是该算法必要的内部变换。
AQ 用 RVQ 初始化，交替 beam 分配与联合最小范数 SVD 求解（相对截断 1e-10，处理码本平移自由度造成的秩亏）。
所有码本最后量化为 Q20 并完整保存；编码端按实际保存的参数重新分配索引。
解码重建使用确定的整数乘加、取整和原生字母表投影，`原码字 XOR 重建码字` 的完整纠错流覆盖
归一化、特殊值、码本量化、OPQ 变换/逆向近似以及重建的全部位模式差异。两端无需重新训练或复现浮点舍入。
索引和纠错分别使用现有 A1 算术编码；码本、变换、指数、两个频率表、流边界及全部封装均计费。
原论文的 VQ/PQ/OPQ/RVQ/AQ 为近似表示，本项目明确称为无损适配，不声称原版无损或仅以原样回退作为有效性证据。

可用 `python3 scripts/build_shared_patterns.py --check` 重跑合成原生 ASan/UBSan 检查，含强制哈希碰撞及非贪心 AQ 反例；不运行模型。
C 原生库为 `build/libfp4_shared_patterns.so`，独立构建且原子替换；来源、固定 commit、许可证、参考代码及差异见
`native/shared_patterns/third_party/sources.json`。Xdelta、Sequitur 和 Eigen 直接复用；其余为核对原文/源码后的明确算法适配，
C3 复用 Eigen SVD 线性代数，自行实现训练流程，不声称使用了 Faiss 原版实现。

`--workers` 没有每项 16 的硬上限。C3 可用 `FP4_C_THREADS=N` 并行分配与编码，默认每工作进程 1 线程，
确定顺序归约；含 C3 或 D 的实验进程池使用 `spawn`，避免继承 OpenMP 状态。增大时应同时考虑块间进程数。
不修改正在运行的 A2 冻结版本或原生库。C/D 真实 FP4 抽样的范围与状态见 README，不将子集当作全模型。

尚未验证的范围：真实模型收益/运行耗时、原 CLI/GIF/TIFF/语法文件的互通、其他 FP4 数值格式、其他码本阶数和维度。
这些不属于当前已验证的固定变体；扩展时要逐项复核格式、训练与参数成本，不将现有无损验证外推为这些结果。

## 码字模式 VQ 无损适配

`vq_codeword` 是独立完整插件，保留 `vq_lossless` 原数值VQ；不把整数码字编号当数值距离。
实际出现的连续完整码字向量作 medoid，码本按原符号4/8-bit packed 保存；8维16中心时为64 bytes，而原Q20码本为512 bytes。
每组件独立分层确定性抖动抽取至多2048个训练向量，避免固定步长与周期模式混叠；五轮分配/medoid更新，原输入/编码顺序保持。
参数为 vector_length=2/4/8、centers=4/16/64（上限，最终剔除未使用中心）、objective=hamming/rate、correction_model=shared/conditioned/auto。
rate 使用平滑频率估计索引及共享XOR纠错码长；这是预计成本训练，不声称全局最优。完整纠错始终保留负零、所有原始位模式。
conditioned 用已恢复索引与向量位置选择纠错CDF，低收益上下文使用共享模型；全部表、回退标记与长度计费。
auto 同时编码共享/条件方案，按实际 payload、base64表及变化的JSON字段长度选择较小完整产物；选择模式写入产物。
索引复用A1缓冲区接口，纠错直接复用同一固定版本YAECL的32-bit区间/24-bit CDF和结束规则。无原样或算术-only回退。
解码只读packed码本、索引、纠错和表，不重新训练、不依赖原checkpoint；4/8-bit组件上限1 MiB，BF16尚不支持。
独立库 `build/libfp4_codeword_vq.so`；`python3 scripts/build_codeword_vq.py --check` 编译并做ASan/UBSan机制与边界检查，不覆盖A/B/C/D旧库。
来源及差异见 `native/codeword_vq/sources.json`。本轮方案/全部候选/结果统一由 README 链接，不另立工程审批流程。

## D 类变换、稀疏与分解

本轮 16 个完整 C++ 插件沿用同一 `arithmetic` 原始输入基线、分块和两种收益，比较类型 `complete_scheme`。
各组件独立处理，scale 不与权重共享训练/变换/编码状态。输入仍是原始数据；仅对应技术内部允许其定义所必需的
BWT/MTF、bit-plane、lifting、基变换及张量展开，输出恢复完整码字、原布局与顺序。
此许可不引入全局字段拆分、重排、转置或自由组合阶段，也不改变 A2/B/C 方法的既定输入方案。

**整数可逆规则。** CDF 5/3 先拆偶/奇采样，`d[i]=odd[i]-floor((even[i]+even[i+1])/2)`，
再 `s[i]=even[i]+floor((d[i-1]+d[i]+2)/4)`；缺少的邻接偶值或 detail 在相应端对称延拓。
每级 `[s,d]` 排列，只递归 s；逆过程先撤 update，再撤 predict。长度1直接保留，奇长度的最后偶值也按此规则处理。
全部预测/更新以 signed int64 计算，每步检查 int32 范围；存储系数为 signed int32，不截断或回绕。
256 样本、原16-bit码字输入的保守界仍在 int32 内；逆向超界明确失败。Haar 则用另一组上述 S-transform 步骤，
其低通为整数均值，不重复包装 5/3。两者都无需原始数据纠错流。

**数值与位模式恢复。** 复用 C3 已核对的原生数值解释、二次幂归一化和完整码字投影；
FP4 数值方法要求 `fp4_value_format=E2M1FN`，FP8/BF16/scale 用原生数值，F32 继续按原始 byte 值处理。
可逆整数方案处理码字整数，不需要推断浮点数值。基、均值、字典、系数、因子、核心均最终序列化为 Q20 signed int32；
量化及 ±256 限幅属于近似表示的环节，全部差异由纠错补齐，不把取整或小误差当成无损证明。
编码端先序列化参数，并实际编码/解码系数流，再调用与解码端相同的整数重建函数，
据此生成 `原码字 XOR 重建码字`。重建只读产物，使用 int64/受界 __int128 乘加与确定性取整，
不重新训练、拟合、求特征向量或 SVD；负零、NaN/Inf、原生 padding 等全部位模式恢复。
DCT/DST 本版明确为带纠错数值适配；核对过整数 lifting/PCT 选项，未将 JPEG-XR PCT 或近似整数 DCT 冒充所声明的变换。

MDCT 使用 `w[i]=sin(pi*(i+1/2)/16)` 与标准半采样相位的16×8 cosine核，满足 `w[i]^2+w[i+8]^2=1`。
分析前加8个零，末尾补至 hop 边界并再加8个零；生成 `ceil(n/8)+1` 帧。
解码按 `2/N=1/4` 合成、乘窗并重叠相加，再去首8个 priming 位置并截回原 n；所有依赖在本组件内。
窗和 cosine 核的实际 Q20 参数全部保存，整数 overlap 累积后一次取整，再计算纠错。
原生检查还在不加纠错时确认浮点 TDAC 重建，避免由纠错掩盖错误窗、缩放或边界。

**形状与编码。** D3 是明确的固定块适配：`block[t]=source[64*b+t]`，矩阵按 `t=8*i+j`，
三阶张量按 `t=16*i+4*j+k`。尾块补零后按原数目截回，参数中记录形状与秩，元素对应关系不变。
这不是对整张原生大张量做一次分解，也不声称小块的结构代表原 tensor 全局结构或硬件访问边界。
CP 的三个4×2因子、Tucker 三因子及核心、TT 三核心采用不同展开和重建公式；没有以同一矩阵低秩函数替代。
Kronecker 内部映射明确为 `R[2*a+b,4*i+j]=X[4*a+i,4*b+j]`，拟合后的逆映射恢复原元素位置。

所有系数/稀疏支持记录/因子核心，采用 ZigZag int32 → 交错低16/高16字序列 → 现有 A1 算术编码；
这是变换表示的序列化，不对其他方法的原 FP4 做字段拆分。BWT/MTF 秩直接算术编码，Bit-plane 各用独立二元模型。
原始纠错是另一个完整码字算术流。共有基/均值/字典、窗、形状、秩、归一化、边界/长度以及全部频率表写入 side information；
变化的系数/支持/因子核心及纠错写入 payload，两项实际序列化字节全部计费。
按现有约定，验证后丢弃 payload，只保留必要模型状态、哈希和效果；不保存可恢复整模型的 checkpoint。
本轮不单列 CSR/CSC、Bitmap、Zero-Run、Coefficient Thresholding、NMF 或 CDF 9/7。

D 每组件上限1 MiB，外层默认分析块仍为权重＋scale合计1 MiB；不跨分析块/层/专家训练或变换。
`FP4_D_THREADS=N` 可并行独立数值块，默认1；D 进程池沿用 `spawn` 避免继承 OpenMP 状态，不改变比较流程。
运行 `python3 scripts/build_math_structure.py` 独立编译，复用已有 A1 与 Eigen，不覆盖 A2 正在使用的库；
`--check` 额外执行合成 ASan/UBSan 核心与边界检查。来源、版本、参考源码、公式及差异见 `native/math_structure/sources.json`。

未完成的范围是：真实全模型收益/耗时、其他变换变体或窗、可配置大尺寸与秩、原生整矩阵/高阶 tensor 的直接分解、
未知 FP4 数值格式和第三方容器互通。这些均未作为当前已验证配置报告，也未以占位插件或零收益代替。

## 查看目录和计划

`methods` 每项只有 id、名称、类别和 `implemented`（是否注册实现）。
已注册 A1 七个、A2 六个、B 十二个、C 十七个方法（VQ 两种适配）和一个关联别名、D 十六个，共 59 个方法 id。进度统一见 README 表格。
`plan` 生成 target × 所选类别方法的组合，全部为 `not_run`；
每项引用 method_id，不重复展开方法说明。E～G 暂无条目，选择后计划为空。
实际运行只使用显式注册的工厂；没有研究状态或有损属性筛选。

## A1 的四个实现

前三种方法采用静态零阶频率模型；Golomb–Rice 每流选择一个固定参数。均由 C/C++ 执行。
基线 id 为 `huffman`、`arithmetic`、`rans`、`golomb_rice`；前三项的指数分离版加 `_fp8_bf16_exp`，
只分离 FP8/BF16 的指数和“符号位＋尾数”。各原生组件分别建模，权重与 scale 不混合。

| storage_format | 编码符号与字节布局 |
| --- | --- |
| `fp4_packed_low_first` / `fp4_packed_high_first` | 按声明的 nibble 次序取完整 4-bit 码字；包括原 padding |
| `F8_E4M3` / `F8_E5M2` | 完整 8-bit；分离版按 4/5-bit 指数及其余位分别编码 |
| `BF16` | little-endian 完整 16-bit；分离版按 8-bit 指数与其余 8-bit 编码 |
| `F8_E8M0` | 独立的完整 8-bit scale，不再拆分 |
| `F32` | 用户指定先按原始字节编码，不拆指数 |

I8 文件头不能独自证明 FP4 packing，未知格式返回不适用，不自动猜测。
产物包含组件 id/角色/格式、长度、流边界、码长/频率表、结束状态、padding 及校验信息，全部计费。
解码只做整数位运算，不将码字转换为浮点数。指数分离是显式比较方案，不保证每个目标更小。
通过 `builtin_registry()` 和 runner 调用；实际内存包含符号、表和产物，
高于原始字节大小。大目标使用下面的分块接口，不能整块读入巨型 embedding。

| 算术编码 | [YAECL](https://github.com/tongdaxu/YAECL-Yet-Another-Entropy-Coding-Library/tree/1011b07d33e67cab01855e6df40afe10372d10a3) | 复用 32-bit 区间、24-bit 整数 CDF；改用缓冲区接口，并为 A2 暴露相同的区间更新操作 |
| rANS | [作者版 ryg_rans](https://github.com/rygorous/ryg_rans/tree/c9d162d996fd600315af9ae8eb89d832576cb32d) | 复用字节 rANS、编码端倒数乘法及状态更新；适配完整 uint16_t 字母表和有界读缓冲区 |

`python3 scripts/build_native.py` 用 `-O3 -march=native` 编译为 `build/libfp4_entropy.so`，
构建信息含编译器、源码与二进制哈希。`builtin_registry()` 接入同一完整方法接口，
原生库不可用时明确失败。
拆完整码字、指数分离、统计和编解码均在 C++ 内完成；Python 只按组件传递缓冲区。
完整符号版 BF16 以完整 16-bit 码字编码；算术编码/rANS 的 CDF 稠密索引映射和频率表完整计费。
指数分离版仅用于 FP8/BF16，其余目标记为 inapplicable，避免重复跑相同的 FP4/F32 流程。
码表/频率表以二进制的 base64 表示存入 side_information，连同实际序列化开销一起计费。
源码、CDF 精度和封装版本均随运行记录保存。

### Golomb–Rice

采用 Golomb 的 Rice 特例 `m = 2^k`，不实现任意 `m` 的通用 Golomb 编码。
复用并适配 [FLAC 官方 Rice 位流循环](https://github.com/xiph/flac/blob/59fa3402cb19b6b7c85b916f138cfb03c7b27504/src/libFLAC/bitwriter.c)，
表示依据 [RFC 9639 §9.2.7](https://www.rfc-editor.org/rfc/rfc9639.html#section-9.2.7)。
保留按机器字输出及前导零计数解码；去除音频有符号折叠、回调和容器依赖，增加有界缓冲区检查。
来源、固定版本、本地差异和 BSD 许可证保存在 `native/third_party/FLAC/` 与 `sources.json`。

码字直接作为无符号整数 `u`，不做数值解量化、预测、差分或码字重映射。
每个块的每个组件流独立选择 `k ∈ [0,16]`，最小化 `sum((u >> k) + 1 + k)`，相同位数取较小 k。
商写成若干个 0 和终止 1，其后按高位在先写 k 位余数。保存 k、有效位数、符号数量和流边界；
最后补零至完整字节，全部参数、头部和 padding 均计费，不需要频率表，也不回退到原样存储。
FP4、FP8、BF16 按原序完整码字编码，scale 始终为独立完整 8-bit 流；不保留 Rice 指数分离版。
该实现按码字整数大小分配码长，不按出现频率重映射码字，也不平移到分布中心。
例如 `k=2` 时，整数 0 编码为 `100`（3 bit），15 编码为 `000111`（6 bit）；
对均匀的 0～15，最优平均码长仍为 4.5 bit，高于 packed FP4 的 4 bit 基线。
浮点数值接近零不等于其原始无符号码字接近零；集中在较大码字附近的分布也未必能被本实现压缩。
支持现有分块、多进程、状态保存与逐字节验证；模型实测结果见运行目录。

Contract No. DE-AC02-06CH11357 with the Department of Energy.

## Checkpoint 与大目标分块

`checkpoint.load_checkpoint` 仅支持用户指定的 `deepseek-ai/DeepSeek-V4.1-Flash`
版本 `2cba9e42aa026125f3ed06c6d98c1db82f7ca027`。只读配置、索引和文件头，
按原文件偏移引用数据，跟随缓存链接，不复制 checkpoint 或执行其中的代码。
检查索引与分片一致、dtype/shape/范围、scale 配对，记录文件头哈希；此阶段不哈希权重数据。
完整覆盖仅指索引中的 tensor payload，不包括原文件头或其他仓库文件。

一个目标为一个原生 tensor 及其伴随 scale。布局依据快照的 `inference/convert.py`、
`model.py` 和 `kernel.py`：FP4 是低 nibble 在先、每行 32 码字一个 scale；
普通 FP8 为 32×32 块，Engram embedding 为每行 32 列。BF16/F32 保留原生形状与位模式。
记录文本/视觉/MTP、层和专家标签；未知硬件行为仍为 unknown。

```bash
PYTHONPATH=src python3 -m fp4_redundancy checkpoint "$SNAPSHOT" --output /tmp/dsv41-manifest.json
PYTHONPATH=src python3 -m fp4_redundancy plan /tmp/dsv41-manifest.json --categories A --chunk-bytes 1048576 --target layers.0.ffn.experts.0.w1.weight
```

`--output` 只创建新文件。无分块参数的旧 `plan` 会展开内存列表，仅适合小清单；
`--chunk-bytes` 惰性输出 JSONL，每行一个块及其方法列表，全部 not_run。

`chunks.iter_target_chunks(target, max_bytes)` 不读数据：量化权重按连续行组切分，
对应 scale 范围只归属一个块；无 scale 的张量按原生标量边界切分（F32 仍按字节编码）。
`runner.evaluate_target_chunks(...)` 逐块读取、编码、新实例解码和验证，逐条 yield 结果，
不保留之前块的产物。块的父目标、原形状、相对偏移及布局信息写入计费产物，可按偏移拼回原张量。
默认原始组件合计上限 1 MiB；上限容不下最小 scale 行组时明确报错，不能拆断依赖或重复 scale。
单目标 `evaluate_target` 也有默认字节上限，超过后要求使用分块接口。
分块是离线存储/内存控制单位，不代表硬件读取单位；Engram 参考实现的逐行访问单独记录，
不声称多行压缩块可直接支持逐行推理读取。各块独立建模，收益会受块大小及表开销影响。

容器解析依据 [safetensors 格式说明](https://github.com/huggingface/safetensors#format)。

## 执行结果

### Payload与元数据

所有技术的报告同时保留三项：`Payload节省率 = 1 − payload_bytes / original_bytes`、独立元数据大小、
`总节省率 = 1 − (payload_bytes + metadata_bytes) / original_bytes`。
先按字节汇总再计算比例；失败/不适用/资源受限的配置留空。相对算术基线的净节省继续按完整总成本计算。
FP4报告使用原packed权重字节作分母，scale独立统计；历史36片段报告沿用原先含独立scale的总组件口径，明确标注。

沿用现有产物的`payload`与`side_information`边界，新增诊断指标，不重编码或挪动字节：

| 方法 | 保留在Payload中的实际编码数据 | 当前独立元数据示例 |
| --- | --- | --- |
| A1/A2 | 熵编码位流、ANS renormalization输出及最终编码状态、算术结束位、Rice商/余数、CAVLC token/level/run | 频率表、符号映射、码表、模型规格；神经模型权重 |
| B | 差分/XOR/精确残差、ADPCM决策与补偿、FPC选择前缀与残差、JPEG-LS原生码流 | LPC系数、LTP lag/gain、滤波/方向/运动参数及各流频率表 |
| C | RLE符号/run、LZ字面量/匹配token、语法根序列、去重引用/字面块、VCDIFF/RLZ指令、VQ/PQ等索引与纠错 | 独立保存的语法规则、参考、码本/旋转、频率表 |
| D | BWT/MTF输出编码、位平面编码、变换系数、稀疏支持/系数、分解因子/核心和精确纠错的编码流 | primary位置、形状/秩、基/均值/字典/窗等共享参数、频率表 |

各码流自身的结束状态、内部头部与字节padding仍属于payload。记录中的`initial_state_hex`等日志副本不改变产物计费。
独立元数据并不等同于“可免费共享的码表”：逐块参数、语法、参考和字典可能随数据增长或携带原始信息，
是否共享仍需独立实现与验证。Payload节省率只作为编码数据流诊断，不能单独当作实际冗余收益。

`runner.evaluate_target` 一次读取一个受大小限制的目标，编码后用新实例解码，比较组件集合和 bytes。
它保存目标/方法/参数、结构和推理信息、输入哈希、编解码时间及下列结果：

| status | 含义 |
| --- | --- |
| not_implemented | 没有注册实现 |
| inapplicable | 当前实现不支持该输入或参数 |
| failed | 读取、编码或解码异常 |
| verification_failed | 恢复的组件或 bytes 不一致 |
| verified | 全部原始 bytes 恢复一致 |

只有 `verified` 才报告大小和节省率：
`1 - (payload_bytes + side_information_bytes) / original_bytes`，允许负值。
其他状态的大小与节省率为 null。验证范围仅限声明的组件，不表示恢复整个 checkpoint 文件。
汇总按字节统计，不平均 tensor 节省率，也不叠加不同方法的收益。

所有方法统一记录以下字段，后续插件沿用同一执行接口，无需单独增加统计：

| 字段 | 含义（大小单位均为 bytes） |
| --- | --- |
| `chunk_bytes_limit` | 配置的块大小上限，按权重和伴随 scale 的原始字节合计 |
| `original_bytes` | 每条块记录的实际原始大小；汇总另列 `chunk_original_bytes_min/max` |
| `payload_bytes` | 压缩数据流大小，不含独立元数据；保留码流自身的结束状态、内部封装和字节 padding |
| `side_information_bytes` | 独立元数据大小，含表、参数、布局及共有头部的实际序列化开销 |
| `total_bytes` | 上述两项之和，即完整压缩产物大小 |
| `saving_bytes` / `saving_fraction` | 相对原始组件字节的节省字节数和比例 |
| `baseline_comparison` | A2/B/C/D 匹配零阶对照的状态、大小和净收益；不适用比较时为空 |

`sizes.csv` 每个方法一行，同时保留已验证原始字节数、覆盖率和状态。
块大小范围描述本次所有已处理块，体积汇总只计该方法的 verified 结果；
全部不适用或失败的方法，其 CSV 体积列留空。SQLite 文件及状态日志自身大小不作为压缩产物大小。

## 模型压缩运行

用户已授权对指定 checkpoint 开始 A 类压缩。结果按技术保存到 `runs/<技术名称>/`，不按日期分目录；
执行时用 `--methods` 选择该技术所保留的版本，示例见 README。
使用原生后端，每块输入合计至多 1 MiB，各适用方法独立编码和逐字节验证。
同块原始数据只读取一次；进程池最多保留两倍 worker 数的在途任务，不展开全模型块列表。
块间通过多进程并行，不跨层/专家编码；不进行推理性能或峰值内存实验。

- `run.json`：模型版本、输入文件指纹、实现哈希、方法/分块配置、原生构建和上游版本。
- `results.sqlite3`：每块的结构、大小、输入/产物哈希、验证结果；`state_zlib` 保存压缩 JSON
  格式的频率/码长表、Rice 参数、流边界、位数和 rANS 初始状态。此压缩仅用于日志，不改变测量的产物大小。
- `progress.json`：运行中进度及各方法按已验证字节统计的效果；完成后另写 `summary.json`。
- `sizes.csv`：从同一汇总导出的块大小、压缩数据、元数据和合计体积比较表。

历史合并运行已按技术拆分数据库和汇总；`run.json` 与 `execution.log` 保留当时完整执行信息，
其中可能包含同一次运行的其他技术。时间仍记录在文件内，用于追踪和计算耗时。

压缩数据流验证后丢弃，不保存压缩 checkpoint 或原文件恢复封装。
状态与结果在一个 SQLite 事务中提交；加 `--resume` 跳过已提交块，并检查配置、代码和源文件指纹未变。
一个运行目录只允许一个写入进程。`--max-chunks N` 明确表示子集实验，不能当作全模型结果。
创建运行目录的 `STOP` 文件后提交在途结果并退出，状态为 stopped；`--resume` 清除标记并续跑。
共有头部开销计入方法总大小；组件/格式/scale 布局分组仅列直接开销，共有头部开销单独显示。
