# 002 账本核对：R1 + 零合并 + scale 条件 + scale 流

基于 spec 001 的结果（提交 `ed53d5e`）。本规格仍是统计测量，不产生码流。

## 0. 目的

001 分别测出四项收益（36 张矩阵中位数，bit/权重）：

| 来源 | 001 中的数 |
| --- | ---: |
| R1 边缘偏斜 `4 − H0` | 0.106 |
| 合并 +0 / −0 | 0.117 |
| 以本块 scale 为条件 `I(C; E)` | 0.127 |
| scale 流 `(8 − H0(E)) / 32` | 0.219 |

四项相加约 0.57 bit/权重（原始 4.25）。相加成立的前提没有直接测过。本规格回答三个问题：

1. 把四项放在一起**直接**测，总数是多少？与分项相加是否一致？
2. 计入码表成本后还剩多少？码表能否在矩阵之间共用？
3. 在 scale 之外再加上块最大码 `m_max` 作条件，扣除标签成本后是否还有净收益？

## 1. 约束

- 沿用 001 的样本（同一选取规则，36 张矩阵）、格式事实和 `diagnostics/` 下已验证的代码；可以在该目录内新增模块。
- 不 import `fp4_redundancy`，不读取 `runs/` 和 001 之前的旧结果。
- 第 4 节的检查通过之前，不在模型数据上运行。
- 只用 NumPy。

## 2. 记号

沿用 001：`C`、`s`、`m`、`E`、`m_max`、块大小 `B = 32`、码字数 `N`。新增：

| 记号 | 定义 |
| --- | --- |
| `C'` | 合并零后的码字：`C == 8` 时取 0，其余不变（15 种取值） |
| `E_rel` | 相对 scale：`E` 减去该矩阵中出现次数最多的 scale 值，裁剪到 [−3, +3] |
| 原始成本 | `4 + 8/B = 4.25` bit/权重 |

`C → C'` 只丢失零的符号。数值表下 `v(C') == v(C)` 对 16 个码字全部成立，这一点写成单元检查。

## 3. 测量项

所有量为 bit/权重，同时给出占 4.25 bit 的百分比。每项报告 36 张矩阵的中位数、最小、最大，以及按层、按角色的中位数。

### M1 码字流的条件熵

对每张矩阵计算下表全部 8 个熵（plug-in，条件熵 = 联合熵 − 条件变量的熵）：

| 条件 | 对 `C` | 对 `C'` |
| --- | --- | --- |
| 无 | `H(C)` | `H(C')` |
| `E` | `H(C \| E)` | `H(C' \| E)` |
| `m_max` | `H(C \| m_max)` | `H(C' \| m_max)` |
| `E, m_max` | `H(C \| E, m_max)` | `H(C' \| E, m_max)` |

另外报告：

- 每个 scale 取值下的 `P(m=0 | E)` 和 `H(s | m=0, E)`。后者应接近 1；它决定"零合并"与"scale 条件"能否相加。
- 每个 scale 取值下的 15 格直方图（写入 CSV），用来直观看到不同 scale 的分布形状。

### M2 标签成本

`m_max` 需要传给解码端。成本为 `H(m_max) / B`（不以 E 为条件时）或 `H(m_max | E) / B`（已有 E 时）。报告：

- `m_max` 的增量净收益 = `H(C' | E) − H(C' | E, m_max) − H(m_max | E) / B`。
- 同一量在 S0（整张矩阵内置换码字，E 不动，`m_max` 重算）上的值，3 次重复。独立数据上应不大于 0。

### M3 scale 流

每张矩阵：`H0(E)`，以及收益 `(8 − H0(E)) / B`。001 已测出相邻 scale 的互信息约 0.0008 bit/scale，本规格不再利用它。

### M4 码表成本与共用

比较三种码表方案下 `C' | E` 的码长：

| 方案 | 码表 | 码长 | 码表成本 |
| --- | --- | --- | --- |
| a 每矩阵一套 | 该矩阵自身的 `P(C' \| E)` | `H(C' \| E)` | `14 · K_E · 12 / N`，`K_E` 为出现过的 scale 取值数 |
| b 全局共用 | 其余 35 张矩阵合并得到的 `P(C' \| E_rel)`（每格加 0.5） | 该矩阵在这套表下的交叉熵 | 0（留一法，表不含被测矩阵） |
| c 按角色共用 | 同 b，但只用同一角色（w1/w2/w3）的其余矩阵 | 交叉熵 | 0 |

scale 流同样比较：每矩阵一套（成本 `K_E · 12 / (N/B)` bit/scale）与全局共用的 `P(E_rel)`（留一法交叉熵；另加每矩阵 8 bit 传"最常见的 scale 值"）。

报告方案 b、c 相对方案 a 多出的 bit/权重。

### M5 总账

每张矩阵：

```
压缩后 = 码字流码长 + 码表成本 + (scale 流码长 + scale 码表成本) / B  [+ m_max 标签成本]
节省   = 4.25 − 压缩后
```

对以下组合各给一行：

1. 仅R1：`H(C)`，scale 不压缩
2. 加零合并：`H(C')`
3. 加 scale 条件：`H(C' | E)`
4. 加 scale 流：`H(C' | E)` 与 `H0(E)`
5. 第 4 行加 `m_max`（含标签成本）
6. 第 4 行改用全局共用码表（方案 b）

同时给出"001 分项相加"的值（`(4 − H(C)) + P(m=0)·H(s|m=0) + I(C; E) + (8 − H0(E))/B`）与第 4 行直接测量值之差。

## 4. 检查

不读模型。形状 1024 × 2048。

| 编号 | 构造 | 通过判据 |
| --- | --- | --- |
| U1 | 数值表 | `v(C') == v(C)` 对 16 个码字全部成立 |
| U2 | 001 的 T1（15 码字独立均匀，scale 取常数） | `H(C) − H(C')` 的绝对值 < 10⁻⁹（码字 8 不出现）；`I(C'; E) = 0`；M5 第 4 行节省 = `(4 − log₂15) + 8/B` ± 10⁻⁴ |
| U3 | 独立 `N(0, 1.68²)`，按块取 `e = floor(log₂ amax) − 2`，除以 `2^e` 后用 001 的量化函数得码字，`E = e` | 恒等式 `H(C) − H(C') = P(m=0)·H(s\|m=0)` 误差 < 10⁻⁹；恒等式 `H(C') − H(C'\|E) = I(C'; E)` 误差 < 10⁻⁹；`I(C'; E)` > 0.05；S0 上 `I(C'; E)` < 10⁻⁴；M2 增量净收益在 S0 上 ≤ 0；"分项相加"与第 4 行之差的绝对值 < 10⁻³ |
| U4 | 把 U3 的数据复制成 3 个"矩阵" | 方案 b 的交叉熵与方案 a 的 `H(C'\|E)` 之差在 [0, 10⁻³] 内 |

**主要结果**（36 张矩阵中位数，bit/权重，占 4.25 的百分比；详见 `summary.md`）：

| 行 | 组合 | 节省 | 范围 |
| --- | --- | ---: | --- |
| 1 | 仅 R1 | 0.106（2.49%） | 0.103–0.146 |
| 2 | 加零合并 | 0.223（5.24%） | 0.220–0.261 |
| 3 | 加 scale 条件 | 0.350（8.23%） | 0.323–0.378 |
| 4 | 加 scale 流 | 0.569（13.38%） | 0.542–0.596 |
| 5 | 第 4 行加 m_max | 0.574（13.50%） | 0.550–0.597 |
| 6 | 第 4 行改用全局共用码表（方案 b） | 0.540（12.71%） | 0.394–0.548 |

1. 直接测得的总数与 001 分项相加一致：第 4 行与分项相加之差在 −1.2e-4 到 −6.1e-5 之间，基本就是码表成本（中位数 6.1e-5）；`I(C';E) − I(C;E)` 约 −2e-7。`H(s|m=0,E)` 在零码字 ≥ 1000 个的 (矩阵, E) 组合上为 0.9988–1.0000。
2. 每矩阵一套码表的成本可以忽略（约 6e-5）。按规格的 `E_rel`（减众数）共用，码字流多 0.020（方案 b）/0.024（方案 c），L39 最高 0.16。原因是主要的两个 scale 取值（2^−7、2^−6）几乎各占一半，众数在 36 张矩阵中 27 张取 2^−7、9 张取 2^−6，`E_rel` 因此整体错一格。补充测量改用 scale 字节本身作共用表的上下文，码字流只多 0.0015（范围 2.5e-5–0.031），第 6 行对应节省 0.568。
3. 加上 m_max 并扣除标签成本，增量净收益为 +0.0047（范围 −0.0020 到 +0.0072，36 张中 35 张为正）。S0 上为 −0.0079（最大 −0.0076），即真实数据上的这点收益不是估计偏差。含全部码表后，第 5 行比第 4 行多节省 0.0046。

**偏离与解释**：
1. 第 1 节限定只用 NumPy，但第 5 节要求输出 `hist_by_scale.png`。计算只用 NumPy；只有这张图用 Matplotlib 绘制（与 001 相同），未安装新包。零计数在对数坐标上不画点。
2. 共用 scale 表：规格把 `E_rel` 裁剪到 [−3, +3]，但对 scale 流本身，裁剪不可逆。实现为 −3…+3 共 7 个符号加 1 个转义符号；超出的 scale 转义后另付 8 bit 原值。36 张矩阵中共 10 个 scale 被转义。共用 scale 表各格加 0.5，众数并列时取较小字节。共用码字表的上下文按规格裁剪（解码端已知 E，裁剪只合并上下文）。
3. 码表成本：规格只给出方案 a 的 `14·K_E·12/N`，第 1、2、5 行按同一写法推广为 (字母表−1)×12 bit/上下文。第 1 行 16 个符号，第 2 行 15 个；第 5 行按出现过的 (E, m_max) 组合计，标签 `m_max|E` 的码表另计 `K_E·7·12/N`。M2 增量净收益按规格公式计算，不含码表成本。
4. 补充测量（规格未要求）：按绝对 scale 字节共用码字表和 scale 表，留一法（全局与按角色），写入 `tables.csv`（`b_absE`/`c_absE`）、`ledger.csv`（行 `6abs`）和 `summary.md`。规格的方案 b/c 及第 6 行照常报告，补充不替代它们，只用来区分“分布不能共用”和“对齐方式不合适”。
5. “001 分项相加”按第 3 节 M5 的公式计算，不含码表成本；第 4 行含码表成本，所以两者之差包含码表成本。
6. `hist_by_scale.png` 每个 scale 一条线，画的是 8 个幅值的分布 `P(m|E)`；15 格 `C'` 直方图在 CSV 中。三张矩阵为 L0.E164.w1、L13.E135.w2、L39.E183.w3。

**限制**：
- 全部为 plug-in 统计量，不是实际码流。码表按 12 bit/概率计，实际码表格式不同时这部分成本会变（量级约 1e-4）。
- 共用表只在 001 的 36 张矩阵内留一法评估，L39 等层间差异是否代表全模型未测。
- 极少出现的 scale 取值（几十到几百个块）上的 `P(m=0|E)`、`H(s|m=0,E)` 噪声较大，例如 2^−8 的直方图在 0.5、1.5 处近乎为零。
