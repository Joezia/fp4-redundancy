# 有损评估框架（lossy_eval）

## 目的

后续所有有损尝试（生成器替换、按专家分配码率、误差整形等）都用同一套评估方法。框架回答一个问题：把专家权重 W 换成重建值 Ŵ 以后，模型行为变了多少。它只评估，不包含任何压缩方法。代码在仓库根目录的 `lossy_eval/`，不放在某个编号实验下；每次使用框架的实验仍按编号放在 `experiments/`，第一次是 018（框架标定）。

## 评估层级

| 层级 | 指标 | 说明 |
|---|---|---|
| A 权重 | 每个矩阵的 NMSE = Σ(W−Ŵ)²/ΣW²（dB），全模型汇总 | 只当横轴 |
| B 层输出 | 局部误差：同一真实输入 X 下，MoE 块输出 ‖ŷ−y‖²/‖y‖²；每个专家对路由到它的 token 单独计。累积误差：扰动流与原始流每层输出隐状态的相对误差和余弦。路由变化：每层 top-k 专家集合与原始流不同的 token 比例 | X 取自原模型在校准文本上的真实激活 |
| C 输出分布 | 与原模型逐 token 的 KL(p‖p̂)、top-1 一致率；两者各自的困惑度（WikiText-2 test、C4 validation 子集） | 端到端最灵敏的指标 |
| D 任务 | 多选题对数似然精度（MMLU、ARC-Easy/Challenge、HellaSwag、PIQA、WinoGrande），以及答案翻转数（原对→错、原错→对） | 题面与打分规则按 lm-evaluation-harness 的定义；生成类任务（GSM8K）在显存允许时另做 |

所有指标都同时报告原模型的值；扰动结果只与同一次运行里的原模型比较。

## 执行方式：逐层执行

一次只把一层放到 GPU 上，把全部样本推过这一层，隐状态留在显存或 CPU，再处理下一层（GPTQ 校准采用的方式）。同一遍里原始流和扰动流并行前进，每层权重只加载一次；Ŵ 也只在处理该层时生成，不需要整模型的 Ŵ 同时驻留。

- 原始流用原始 MXFP4 权重；扰动流用 Ŵ。局部误差用原始流的输入再算一次扰动 MoE。
- 只替换 FP4 专家权重；注意力、路由、共享专家、嵌入、输出头等保持原样。
- 只需要一次前向的指标（B、C、多选题）都能这样算。生成任务每个 token 都要走完全部层，不用这种方式。
- 注意力使用因果掩码加右侧填充，填充位置不影响真实 token；按长度分组减少填充。

## 实现要点（gpt-oss）

- **专家权重：** 专家权重以打包的 MXFP4 留在 CPU 固定内存，处理到某层时才搬上 GPU 并反量化为 bf16（MXFP4 的值在 bf16 中可精确表示）。GPU 1 与其他用户共享，可用显存约 15 GB。
- **MoE：** 每层对一个 chunk 的全部真实 token 一起计算，按专家排序分组，没有填充 token。
- **注意力：** 默认使用 PyTorch memory-efficient SDPA，它返回 log-sum-exp；sink 精确地按 out·sigmoid(lse − sink) 计入。对同一组 bf16 的 q/k/v，与 float64 参考的相对误差为 0.1%–0.5%。transformers eager（bf16 softmax）为 0.6%–5.5%，而且慢 10–17 倍。与 transformers 逐位比较时使用 eager 模式。
- **数值下限：** bf16 下，同一序列单独计算和与长序列一起填充计算，结果有舍入差异。MoE 的 top-k 选择是离散的，个别接近平局的 token 会因此换路由，最终 KL 最大约 0.003。低于这个量级的扰动效果不可分辨；标定里用 −40、−30 dB 的极小白噪声来量这个下限。

## 方法接口

一种有损方法是一个对象，框架逐个矩阵调用它：

- 输入：模型名、层、专家、角色（gpt-oss 为 `gate_up`/`down`，DeepSeek/Kimi 为 `w1`/`w3`/`w2`）、原始码值和块 scale、反量化后的 W（float32，存储形状）。
- 输出：Ŵ（与 W 同形状的浮点张量），以及可选的码率信息（只作为横轴）。
- 方法需要真实激活时，可以声明需要；框架把该层原始流里路由到该专家的输入交给它（后续扩展）。

## 模型

1. **gpt-oss-20b**（openai/gpt-oss-20b，revision 6cee5e8）：24 层，每层 32 个专家，top-4；专家权重 MXFP4（E2M1 + 每 32 个一个 E8M0 scale），其余 BF16。用于开发和完整标定。A6000 没有 FP4 张量核，专家在用到时反量化为 BF16 计算。
2. **DeepSeek-V4.1-Flash**：本地完整权重和官方 `inference/model.py`，逐层执行。参考代码依赖的 Hopper 内核改为 BF16 计算，需先确认原模型困惑度合理。
3. **Kimi-K3**：放在后面。

## 正确性检查

- MXFP4 反量化与 transformers 的实现逐元素一致。
- Ŵ = W（恒等方法）时，扰动流与原始流逐位相同，KL = 0，翻转数 = 0。
- 逐层执行的 logits 与整模型常规前向在数值误差内一致（gpt-oss，少量样本）。
- 原模型困惑度和多选题精度处于合理范围。gpt-oss 是推理型对话模型，官方成绩在推理模式下测得，不直接可比。

## 018：框架标定

在 gpt-oss-20b 上对全部专家施加已知扰动，确认指标随误差单调，量级与文献相符：

- 白噪声：每个矩阵加高斯噪声，使权重 NMSE 为 −40、−30、−20、−15、−10、−5、−2.4、0 dB。−2.4 dB 是 10% 码率对应的率失真下界；−40、−30 dB 用来测数值下限。
- 分组舍入：每行每 32 个元素一组，用 bf16 的 absmax scale 做对称均匀舍入，分 4、3、2 bit（每权重 4.5、3.5、2.5 bit）。
- 恒等方法：作为零误差检查。
- 评估集：WikiText-2 test 和 C4 validation 各 64 个 2048 token 窗口（不加 BOS）；每个多选任务最多 2000 题，用固定种子 20261126 抽样，题量不足 2000 的任务全部使用。

模型和数据集按固定 revision 下载到 `data/lossy_eval/`（不进 git），`manifest.json` 记录 revision 和文件列表。由 `python -m lossy_eval.fetch` 下载。
