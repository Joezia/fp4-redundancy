## 0. 目的与总原则

**目的：** 尽可能忠实地复现两篇论文的方法，先在论文自己的设置上验证复现正确，再用到 DeepSeek FP4 权重上，做详细实验。

- **SeedLM：** Shafipour 等，ICLR 2025，arXiv:2410.10714。
- **BB-ANS：** Townsend、Bird、Barber，ICLR 2019，arXiv:1901.04866。

**总原则（最重要）：**

1. **以原文为准。** 每一个实现细节（参数、公式、数据处理、搜索过程、编码格式）都要先从原文（正文、附录、公式、表格）和官方代码中找依据，并在报告里写出处（节号、公式号、表号，或代码文件与行号）。
2. **不得自行简化。** 不允许根据自己对原理的理解来简化设计，也不允许预先推测结果、据此删减实验。原文写明了的，照原文做。
3. **原文没写清楚的，才允许做选择。** 这时要做到：
   - 先查官方代码；
   - 仍不清楚，就查第三方复现，只能作为参考；
   - 最后才自行决定。
   每一处这样的决定都要记录在 `report.md` 的"实现决定"表中：原文怎么说、为什么需要决定、选了什么、有没有备选。
4. **用到 FP4 时，原文方法的适配要尽量少。** 不得不改的地方，单独列在"FP4 适配"表中，并说明原文对应的做法。
5. **先验证、后扩展。** 每个方法都先在论文自己的设置上复现出接近论文的数字；复现不通过，不得进入 FP4 实验。
6. **夜间无人值守：**
   - 遇到不确定的问题，按以上原则自行决定并记录，不要停下来等待。
   - 只有遇到**无法绕过的阻碍**（下载不到原文要求的模型或数据、官方代码完全无法运行）才跳过该步骤：在报告中写清原因，继续做其他不依赖它的部分。
   - 每个阶段结束都 commit 并 push。中途中断后要能从断点续跑。

## 2. 通用约定（FP4 部分）

沿用 010、011 的约定：

- **数据：**
  - 主样本为 010 的 48 个矩阵：24 个训练矩阵用于训练和选参，24 个测试矩阵（即 011 的 T1）用于报告。
  - 最终结果补跑 011 的 T2。
  - 需要更多训练数据时，可以使用 011 的训练池，不得与 T1、T2 重叠。
- **字母表：** 码值按 R10 合并 ±0 之后的 15 个符号。
- **参考基准：** "008 链式模型 + 011 R9c"在同一批矩阵上的总码长，包括 scale 流。T1 上是 3.6056 bit/权重。可部署方案的对照：011 的 B2（决策树，净收益 +0.0558）和 B3（块内串行版 +0.0549，完全并行加粗块标志 +0.036）。
- **单位：** bit/权重；同时给出占 4.25 bit 的百分比。
- **无损验证：** 凡是声称无损的方案，都要在测试矩阵上实际编码、实际解码，确认码值逐位一致。
- **结果保存：** 模型文件（`*.pt` 等）不提交，记录 sha256 和参数量。不得在测试矩阵上调参，不得编造数字。

## 3. 第一部分：SeedLM

### 3.1 阶段 S1：按原文实现

从原文中逐项找出并实现以下内容，每项都要写出处：

- **LFSR：** 位宽 K、反馈多项式（抽头位置）、状态更新方式、从状态序列取值的方式，以及把整数映射成矩阵元素的方式（包括归一化）。
- **随机矩阵 U（C × P）的生成规则：** 种子怎样决定 U。
- **分块方式：** 块长 C，块怎样沿权重矩阵切分。
- **每块的求解：**
  - 对每个候选种子生成 U，求投影系数（原文中的伪逆或最小二乘）；
  - 按原文量化系数：4 bit 补码，加上每块共享的 4 bit 指数，指数取 2 的幂；
  - 按原文的误差度量选出最好的种子。
  - 原文说预先计算并缓存伪逆，也照做。
- **配置：** 原文表 1 的两种配置：
  - 4 bit：C = 8，P = 3，K = 16；
  - 3 bit：C = 12，P = 4，K = 16。
- **原文中的其他处理：** 如权重预处理、按块归一化、异常值处理等，若原文有写，一律照做。
- 用第三方复现作对照：在同一个小矩阵上比较两边选出的种子和重建误差。不一致时以原文为准，并记录差异。

### 3.2 阶段 S2：在原文的设置上验证复现

- 从原文实验中选一个模型和指标来复现：优先选原文报告过的、规模最小的 Llama 模型（例如 Llama 2 7B 或 Llama 3 8B），指标为 WikiText-2 困惑度和/或原文的零样本任务。数据和评测设置以原文为准。
- 模型从官方渠道获取（Hugging Face 上的官方仓库）。若因权限无法获取，依次尝试原文中出现的其他模型；都无法获取时，记录原因，只做"重建误差层面"的验证（与第三方复现对照），并在报告中明确标为"未完成端到端复现"。
- **通过标准：** 复现得到的困惑度或精度与原文相差在合理范围内（自行设定阈值并说明理由，例如困惑度相对差 ≤ 3%）。不通过时先排查实现；仍不通过，在报告中写明差距，然后再进入 FP4 阶段。

### 3.3 阶段 S3：用于 FP4

FP4 权重的"原值"就是反量化后的数值（码值 × 2^scale）。原文从 FP16 出发，这里改为从这些数值出发，这是唯一的输入适配。

**S3-a 原文方法原样运行（有损）**
- 对 T1 的每个矩阵，用两种原文配置运行 SeedLM。
- 报告：
  - 每权重比特数（原文的计算方式）；
  - 相对 FP4 数值的重建误差：相对均方误差；以及重建值四舍五入到最近 FP4 格点后，与原码值不同的比例；
  - 与 FP4 本身的 4.25 bit 对比。
- 本阶段不评测模型精度（有损线暂缓）。

**S3-b 改造成无损（"近似 + 残差"）**
- 先按 S3-a 得到每块的种子和系数（作为边信息，按原文的比特数计）。
- 解码端用种子和系数重建近似值 ŵ，再以 ŵ 为条件编码真实码值：码长 = −log₂ p(码值 | ŵ 落在哪个区间, 块 scale)。概率用顺序自适应计数（与 008 相同的方法），把 ŵ 按与 FP4 格点的相对位置分档作为上下文。分档方式在训练集上选。
- 总码长 = 边信息 + 条件码长 + scale 流。与参考基准比较净收益。
- **变体（在原文配置之外另行标注为"扩展"）：**
  - 块长取 8、16、32，使块与 MXFP4 的 32 元块对齐或整除；
  - P 取 1–4；
  - 种子位数 K 取 8、12、16。
- 报告每个变体的边信息、条件码长、净收益；并画出"边信息 vs. 条件码长"的曲线。

## 4. 第二部分：BB-ANS

### 4.1 阶段 B1：运行官方代码，复现原文结果

- 克隆官方仓库 `bits-back/bits-back`，按其 README 配置环境。旧版本依赖难以安装时，可以在独立的虚拟环境中安装原版本；实在无法运行，再改用作者的 Craystack 库中对应的 MNIST 示例，并记录原因。
- **复现原文表 2：**
  - 二值化 MNIST：BB-ANS 0.19 bit/维，测试集 ELBO 0.19；
  - 完整 MNIST：BB-ANS 1.41 bit/维，测试集 ELBO 1.39。
- 优先用官方提供的训练好的模型；没有，就按原文和代码训练。
- **通过标准：** BB-ANS 的实际码长与原文相差 ≤ 0.02 bit/维；实际码长与负 ELBO 的差距和原文一致（约 1%）；实际编码、解码逐位一致。
- 记录原文所说的初始比特（约 400 bit）在复现中是多少。

### 4.2 阶段 B2：用于 FP4

**数据点的定义（FP4 适配，写入适配表）：** 一个 32 元块是一个数据点。
- 观测值：块内 32 个码值（15 个符号）。
- 块的 scale 先单独解码（与 008 相同），作为已知条件输入模型。
- 编码顺序：所有块串成一条 BB-ANS 链；或者按原文和 Craystack 的向量化方式，分成多条并行的 ANS 流。两种都做，见下面"并行性"。

**模型（尽量沿用原文的 VAE 结构）：**
- 编码器、解码器的网络形式、潜变量维数、潜变量的离散化方式（原文对连续潜变量按先验分桶），一律按原文和官方代码设置。
- 唯一的适配是似然：原文用伯努利分布（二值化 MNIST）和 beta-二项分布（完整 MNIST）；FP4 码值是 15 个类别，所以解码器输出每个位置的 15 类分类分布。块 scale 作为解码器（以及编码器）的附加输入。
- 网络规模可以按原文规模起步，再在训练集上扩大，选验证集 ELBO 最好的。

**训练：** 在训练矩阵的块上训练，留出 10% 作验证。

**编码与报告：**
- 在 T1 的 24 个测试矩阵上**实际**运行 BB-ANS 编码和解码，确认逐位一致。
- 报告：
  - 实际码长（含初始比特）、负 ELBO，以及二者之差；
  - 码值部分的码长、加上 scale 流的总码长；
  - 与参考基准（链式 + R9c）、011 B2、B3 的比较；
  - 模型成本：参数量 × 16 bit，分别摊到测试矩阵和全模型。
- **并行性：** 分别报告"单条链"和"每个矩阵分成 N 条并行流（N = 1、64、1024、16384）"的码长，以及初始比特随流数增加的开销。
- **解码速度：** 在 CPU 和 GPU 上实测的解码吞吐（码值/秒）。

### 4.3 阶段 B3：离散潜变量（扩展，标注为"扩展"）

- 原文针对的是连续潜变量；Craystack 支持离散潜变量。这一阶段把 005 的"块潜在类别混合模型"（K = 16、32 个块类型，以块 scale 为条件）用 BB-ANS 实际编码，验证 005 用边际似然估计的约 0.073 bit/权重能否用真实编码器兑现。
- 报告内容与 B2 相同，并与 B2 的连续潜变量版本比较。
